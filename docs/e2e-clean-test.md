# 纯净端到端测试说明（新用户视角）

**目的**：模拟一个从未用过 Airpipe 的新用户，从装机、授权、配对到四类核心链路，全手动走一遍，确认原型可用。

> 本文档只供**手动操作**参考。清理动作已由工具执行完毕，测试全程由你自己完成。

---

| 手机：Airpipe `com.morethan.airpipe` | `adb uninstall` | ✅ 已卸载（身份证书、配对库、已授权限随之全部清除） |

## 1. 前置准备

1. **同一 WiFi**：手机与 PC 同一局域网（校园网级大平面网可能链路层禁互访，不通就换手机热点）。
2. **构建 PC 端**（任选 debug / release）：
   ```bash
   cd pc
   cargo build --release            # 产物 target/release/ap
   ```
3. **构建手机 APK**：
   ```bash
   cd android
   mise exec -- ./gradlew assembleDebug
   # 产物 app/build/outputs/apk/debug/app-debug.apk
   ```

---

## 2. PC 端：启动守护进程

```bash
~/GitHub/temp/airpipe-pc/target/release/ap daemon --no-tray
```

- 前台阻塞，另开终端跑其它命令；`-v` 开调试日志（排查时用）。
- `--no-tray`：niri 没有托盘常驻区时用；如果你在 waybar / KDE / Sway 等有 StatusNotifier 宿主的环境，去掉该参数顺便验证托盘。
- 验证：`ap status` 应显示「运行时长、无手机、队列 0、无配对设备、收件目录、端口 17580」。

---

## 3. 手机端：安装 + 新用户授权仪式

### 3.1 安装（传统方式，不用 adb）

1. 把 APK 弄到手机上：USB 数据线拷到手机存储 / 发到微信「文件传输助手」后下载 / 网盘下载，任选。
2. 手机文件管理器找到 `app-debug.apk` → 点开 → 提示「允许安装未知来源应用」时允许 → 安装。
   - 若之前装过旧版，直接覆盖升级即可（同签名）。

### 3.2 一次性授权（三步，缺一不可）

1. **存储权限（所有文件访问）**：打开 Airpipe App → 引导页点「**① 开启存储权限（所有文件访问）**」按钮 → 跳系统页面 → 打开开关 → 返回 App，状态应变为「✅ 已开启」。
   - 若按钮跳转失败，手动路径：设置 → 应用设置 → 应用管理 → Airpipe → 权限 → 「文件和媒体」→ 允许管理所有文件。
   - **不需要 adb，不需要电脑**。
2. **通知权限**：手机 设置 → 通知与状态栏 → 通知管理 → Airpipe → **允许通知**。
   ⚠️ 必须给**这个新 App**，之前给旧探针 App 的不算数；HyperOS 的智能通知管理可能自动把新 App 的通知关掉，若常驻通知消失，回这里重新打开。
3. **省电无限制 + 自启动**：设置 → 应用设置 → Airpipe → 省电策略选「无限制」、自启动开启。

---

## 4. 配对（首次）

1. PC 端开配对窗口（60 秒内完成下一步）：
   ```bash
   ap pair
   # 打印 6 位码，如 123 456
   ```
2. 手机打开 Airpipe App → 配对页 → 输入这 6 位码 → 提交。
3. 成功标志：
   - PC：`ap pair` 退出码 0，日志出现 `HELLO from <手机名>`；
   - 手机：常驻通知显示「Airpipe — 已连接 <PC名>」；
   - `ap status` 显示「手机 已连接」；`ap devices` 出现一条记录。

## 5. 核心链路测试矩阵

每项都有明确 PASS 判据；全部通过才算端到端达标。

### T1 剪贴板：PC → 手机（零点击自动）

| 步骤 | 操作 |
| :--- | :--- |
| 1 | PC 复制任意文本（GUI Ctrl+C 或 `wl-copy "hello"`） |
| 2 | 手机上任意输入框长按 → 粘贴 |

- **PASS**：手机剪贴板已是该文本，全程无点击。
- **回声抑制**：PC 剪贴板不应被这次同步回弹改变。

### T2 剪贴板：手机 → PC

| 步骤 | 操作 |
| :--- | :--- |
| 1 | 手机复制一段文本 |
| 2 | 点一下 Airpipe 常驻通知本体（通知 = 同步，不会打开 App） |
| 3 | PC 上 `wl-paste` |

- **PASS**：`wl-paste` 输出手机刚复制的文本。
- 备选路径：手机选中文字 → 分享 → Airpipe，效果相同。

### T3 文件：PC → 手机

| 步骤 | 操作 |
| :--- | :--- |
| 1 | PC 准备测试文件（建议 ≥10 MiB 考验分块，另备一个小文件） |
| 2 | `ap send <文件> [<文件2> <目录>...]`（`-` 为 stdin） |
| 3 | 手机文件管理器 → 内部存储 → `Airpipe` 文件夹查看 |

- **PASS**：`ap send` 提示发送成功（成功即代表手机回执的 sha256 已被 PC 校验一致）；文件大小一致、能正常打开；目录结构原样重建。
- 深度校验（可选，手头有 adb 时做）：
  ```bash
  sha256sum <PC文件>
  adb shell sha256sum /storage/emulated/0/Airpipe/<文件名>
  # 两端一致
  ```

### T4 文件：手机 → PC

| 步骤 | 操作 |
| :--- | :--- |
| 1 | 手机文件管理器（或相册）选中文件 → 分享 → Airpipe |
| 2 | PC 查看 `~/Airpipe/from_phone/` |

- **PASS**：PC 弹桌面通知（名称/大小）；文件落在 `from_phone/`，哈希与手机端一致；此时 Ctrl+V 可直接粘贴该文件（文件引用已写入剪贴板）。

### T5 掉线入队 → 重连自动补发

| 步骤 | 操作 |
| :--- | :--- |
| 1 | 手机开飞行模式（或关 WiFi），等 `ap status` 显示离线 |
| 2 | PC `ap send <文件>` → 提示「已入队」；`ap status` 队列 +1 |
| 3 | 手机恢复网络 |
| 4 | 等待手机自动重连（退避最多约 60s） |

- **PASS**：重连后**自动补发**，无需任何手动操作；文件哈希一致；队列归 0。
- **边界说明**：手机断网后 PC 最长约 30s 才判死链，期间 `ap send` 会尝试发送并失败重排——**不丢数据**，最迟在重连后自动补发（整体延迟 ≤1 分钟量级）。

### T6 免配重连（TOFU）

| 步骤 | 操作 |
| :--- | :--- |
| 1 | 任选一种：手机重启 / 杀 App 重开 / PC `ap stop` 后重启 daemon |
| 2 | 观察重连 |

- **PASS**：自动重连成功，**无需再次配对**。

## 6. 常见问题速查

| 现象 | 原因 / 处理 |
| :--- | :--- |
| 手机连不上 PC | UDP 广播不可达 → 配对页输 PC 的 `IP:17580` 手动直连 |
| 换网络后失联 | 校园网大平面限杀互访 → 换手机热点 |
| 常驻通知消失 | HyperOS 智能通知自动屏蔽 → 通知管理重开（见 3.2-②） |
| `ap` 命令报 exit 2 | daemon 没起 → 先跑 `ap daemon` |
| 收件目录无写入 | 「所有文件访问」没开 → App 引导页点「① 开启存储权限」按钮（见 3.2-①） |
| 剪贴板不同步 | Wayland 合成器需支持 `wlr-data-control`；X11 未支持 |
